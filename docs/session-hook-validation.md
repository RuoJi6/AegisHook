# 会话状态与子 Agent Hook 验证

验证日期：2026-09-09。控制台使用 `127.0.0.1:18790` 和独立 `.data/test`，通过内置浏览器安装项目 Hook、检查接入状态和审批。测试项目只放置无害标记文件。Codex 与 Grok 的模型连接使用本机 7897 代理，Hook 回调直连回环地址。

## 状态修复

安装配置、历史接入验证、当前会话状态分别展示。会话结束、心跳过期、服务重启或重新注册后失去当前安装绑定，均不能抹掉已收到事件的历史证据。入口被改坏或卸载仍独立显示，不因历史验证成功而显示为正常安装。

持续在线仅用于有心跳的连接；事件型连接显示“事件接入”，30 秒内收到事件或审查心跳时另标“最近活跃”。列表优先显示持续在线或近期活跃的会话。

Codex CLI 从 0.142.0 升级至官方 npm 0.153.4。桌面应用内置运行时也是 0.153.4，但调用其二进制的 `exec` 仍属于命令行测试，不等于在桌面任务中实测。页面检测的版本来自 `PATH` 中的 CLI，同一安装范围收到事件也不能证明 CLI 与桌面端均已验证。

Codex 的项目配置层必须真正受信任，Hook 定义信任是另一层检查。本次早期命令行信任参数未使项目层生效；通过本机配置接口确认禁用原因，给临时项目添加精确信任后才收到事件。这些早期执行不计入 Hook 覆盖通过结果。

Grok 初次无交互调用被客户端权限流程取消；另一次工作流尝试没有完成原生子任务，也不计入通过结果。最终通过的是明确的原生 `spawn_subagent` 加子会话 `read_file` 路径，保留 AegisHook 人工审批。已有历史记录中仍有一次工具数量差异未解释，不能据本次成功声称所有历史调用均完整覆盖。

## 回归范围

新增无监听端口的测试覆盖五种 Agent 的历史接入验证，包含旧记录、会话结束、失联、服务重启、无当前绑定的重新注册、入口损坏、卸载、跨 Agent 证据隔离及忽略调用方伪造的历史字段。相关安装与会话回归通过，生产构建通过。

浏览器验证包含安装状态与接入验证分列、已结束与重启状态、最近活跃的颜色和排序、活跃过期、历史证据保留，以及桌面和手机宽度。测试数据与真实控制台数据分开，临时 Hook 和新增项目信任在测试结束后清理。
